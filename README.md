# GameShelf 🎮

**GameShelf** — Android-приложение для поиска видеоигр, ведения личной коллекции и анализа игровой активности. В нём можно находить игры по каталогу IGDB, сохранять их в свою библиотеку, отмечать прогресс прохождения и просматривать статистику. Дополнительно реализовано подключение Steam-профиля: загрузка библиотеки, синхронизация игрового времени и просмотр активности.

> **Статус:** самостоятельный учебный/портфолио-проект с реализованными основными пользовательскими сценариями. Приложение не опубликовано в Google Play.

## Возможности

### Каталог и поиск

- Поиск игр с постраничной загрузкой результатов.
- Быстрые фильтры по жанрам и платформам; тематические подборки игр с высокими оценками.
- Экран подробной информации об игре: описание, дата выхода, обложка, скриншоты, жанры, платформы, разработчики и издатели, рейтинги и ориентировочное время прохождения.

### Личная коллекция

- Сохранение игр в локальную библиотеку Room.
- Статусы **«Буду играть»**, **«Играю»**, **«Прошёл»**, **«Бросил»**.
- Личные оценки, учёт игрового времени и дополнительные сведения о прохождении.
- Фильтрация, сортировка, редактирование и удаление сохранённых игр.
- Доступ к сохранённой коллекции без подключения к сети. Для поиска новых игр и загрузки данных из внешних сервисов требуется интернет.

### Статистика

- Сводка по коллекции: распределение игр по статусам, оценкам и жанрам, игровое время.
- Отдельная статистика Steam с выбором периода **неделя / месяц / год**.
- Просмотр игровой активности и истории синхронизации Steam-данных.

### Интеграция Steam

- Привязка Steam-профиля по ссылке, загрузка списка принадлежащих аккаунту игр и сведений об игровом времени (при доступности данных через Steam API).
- Хранение профилей и снимков данных о библиотеке локально.
- Синхронизация с учётом изменений игрового времени между обновлениями.
- Переход от Steam-игры к странице в каталоге IGDB через сопоставление **Steam App ID ↔ IGDB Game ID**. Если однозначного соответствия нет, приложение не подменяет его догадкой по названию.

## Технологии

| Область | Инструменты |

## Как устроено приложение

```text
Compose UI (Search / Details / Collection / Statistics / Steam)
                         │
                         ▼
                  ViewModel + UI State
                         │
                         ▼
                      Repository
                    /            \
                   ▼              ▼
        Room / DataStore       Retrofit / OkHttp
                                     │
                                     ▼
                              Cloudflare Worker
                                /           \
                               ▼             ▼
                            IGDB API     Steam Web API
```

**UI и состояние.** Экраны написаны на Compose. ViewModel отвечает за загрузку данных, обработку действий пользователя и предоставление UI-состояния. Например, `CollectionViewModel` формирует реактивное состояние коллекции, объединяя выбор фильтра и сортировки с потоками Room через `combine`, `flatMapLatest` и `stateIn`.

**Repository.** Работа с локальной библиотекой, внешним игровым каталогом и Steam разделена по репозиториям (`LocalGamesRepository`, `GamesRepository`, `SteamRepository`). DTO сетевого слоя преобразуются в модели, используемые экранными компонентами.

**Dependency Injection.** `DefaultAppContainer` вручную создаёт и предоставляет Room Database, Retrofit/OkHttp и репозитории; экземпляр контейнера доступен через класс `Application`. Это позволяет не создавать зависимости непосредственно внутри UI.

**Локальные данные.** Room хранит сохранённые игры и данные Steam: профили, библиотеку, историю синхронизации и соответствия Steam/IGDB. В репозитории присутствуют схемы и последовательные миграции базы данных до версии **6**. DataStore используется для параметров подключения Steam.

## Технические решения

### 1. Cloudflare Worker вместо прямых запросов к IGDB и Steam

Android-клиент обращается к собственному Worker по HTTPS. Worker выполняет запросы к IGDB и Steam, обрабатывает авторизацию IGDB через Twitch OAuth и возвращает данные приложению. **Секретные ключи внешних API хранятся в конфигурации Worker, а не в Android APK.**

Worker также реализует проверку параметров, единый формат ошибок, постраничную выдачу и серверное кеширование отдельных публичных ответов. Исходники находятся в [`cloudflare-worker/`](cloudflare-worker/).

### 2. Реактивные данные и офлайн-коллекция

Сохранённые игры хранятся в Room и доступны без сети. Изменения статуса, рейтинга и игрового времени отражаются на экранах через наблюдение за локальными данными. Внешний каталог и поиск требуют подключения к API; весь IGDB-каталог на устройство не кешируется.

### 3. Синхронизация Steam и расчёт статистики

Steam-данные сохраняются локально. При последующих синхронизациях приложение сопоставляет актуальные значения игрового времени с предыдущими данными, записывает историю обновлений и рассчитывает активность. Для периодов, которые нельзя надёжно восстановить из доступных данных, предусмотрено отдельное представление *untracked* времени.

### 4. Сопоставление Steam и IGDB

Для перехода к подробной информации игры Worker ищет соответствие Steam App ID в `external_games` IGDB. Результат может быть `exact`, `unmatched` или `ambiguous`. Ответ кешируется локально, причём для точного совпадения и для неопределённого результата используются разные сроки повторной проверки.

## Запуск

### Android-приложение

1. Клонировать репозиторий:

   ```bash
   git clone https://github.com/Tempelvil/GameStt.git
   ```

2. Открыть корневую папку проекта в Android Studio и дождаться Gradle Sync. Для запуска потребуется устройство/эмулятор с **Android 8.1 (API 27)** или новее.
3. В корневом `local.properties` задать адрес своего развернутого Worker:

   ```properties
   WORKER_BASE_URL=https://YOUR-WORKER.workers.dev/
   ```

4. Выбрать конфигурацию `app` и запустить приложение.

`WORKER_BASE_URL` используется в `BuildConfig`; Android-клиент автоматически обращается к маршрутам `/v1/` на указанном сервере.

> В текущем `app/build.gradle.kts` предусмотрен URL Worker по умолчанию. Для воспроизводимого локального запуска рекомендуется использовать **собственный** Worker и явно указать его адрес. `local.properties` — локальный файл, его не следует публиковать с секретными значениями.

### Cloudflare Worker

Для полноценной работы каталога и Steam-интеграции нужен Cloudflare Worker с секретами:

```text
IGDB_CLIENT_ID
IGDB_CLIENT_SECRET
STEAM_API_KEY
```

Подробная документация по эндпоинтам и развертыванию находится в [`cloudflare-worker/README.md`](cloudflare-worker/README.md). Не добавляйте токены и ключи в репозиторий или Android-приложение.
